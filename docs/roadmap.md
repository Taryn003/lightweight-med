# 项目专业化路线图（简历导向）

## Phase 1: 原型验证（当前）

- 目标：打通影像 + 病历输入与结构化报告输出
- 交付：CLI 与 Web Demo
- 指标：
  - 单例推理可用
  - 输出格式稳定（含 6 个固定栏目）

## Phase 2: 数据工程

- 数据源：MIMIC-CXR-JPG + 报告文本（获批后）
- 任务：
  - 清洗 image-report 对
  - 构建训练/验证/测试划分
  - 增加质量过滤（缺失字段、过短报告、低质量图像）
- 指标：
  - 数据可追溯（样本ID、来源、版本）
  - 可复现切分脚本

## Phase 3: 训练与蒸馏

- Teacher：Qwen3-VL-4B-Instruct（LoRA）
- Student：Qwen3-VL-2B-Instruct（蒸馏）
- 任务：
  - 监督微调（SFT）
  - 蒸馏损失（logits + task loss）
  - 医疗术语输出约束
- 指标：
  - 报告任务得分（BLEU/ROUGE/BERTScore）
  - 分类任务得分（AUC/F1）
  - 相比 Teacher 的性能保留率

## Phase 4: 轻量化部署

- 量化：INT8/INT4（按硬件选择）
- 部署：FastAPI + Gradio/前端页面
- 任务：
  - 推理服务化
  - 结构化日志与错误处理
  - CPU/GPU 混合部署策略
- 指标：
  - P50/P95 推理时延
  - 显存占用
  - 吞吐量 QPS

## Phase 5: 临床可用性增强

- 医生可编辑报告
- 人工反馈闭环（用于后续增量训练）
- 风险提示与不确定性披露

## 简历建议写法

- 基于 Qwen3-VL 构建基层医疗多模态（影像+病历）辅助诊断系统，支持结构化报告自动生成。
- 使用 MIMIC-CXR 开展 LoRA 微调与 Teacher-Student 蒸馏，实现模型从 7B 到 3B 的轻量化迁移。
- 通过量化与服务化部署将推理资源开销下降，并保持关键任务性能。
- 设计医生可编辑的人机协同闭环，提升系统在基层场景的可落地性与安全性。
